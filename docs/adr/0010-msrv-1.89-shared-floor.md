# ADR-0010: MSRV 1.89.0, one floor shared with the maintainer's other crates

- **Date:** 2026-10-13
- **Status:** Proposed

## Context

The README's MSRV policy says the floor is set by dependencies and rises
only when a dependency requires it or a language feature removes real
complexity. On v0.0.68 the dependency floor is 1.88: `time-macros`,
`staticdatagen` and the `oxc_*` crates declare it. Nothing in the
dependency graph needs 1.89.

The maintainer's Rust crates declared floors between 1.56 and 1.92, so
the support promise differed for every crate a user combined.

## Decision

`rust-version` is 1.89.0 for the `ssg` package and every workspace
member, the floor the maintainer chose for all of his Rust crates. It
is the one raise made without a dependency reason; the README policy
governs every later raise.

## Consequences

- Positive: one floor across the maintainer's crates; the MSRV CI legs
  now set `RUSTUP_TOOLCHAIN`, so they build on the floor instead of on
  the stable toolchain that `rust-toolchain.toml` selects.
- Negative: users on 1.88 lose new releases with no technical gain.
- Neutral: the floor covers the library and binaries. The test suite
  needs rustc 1.93.1 (`serial_test` 4), as it already did under 1.88;
  the MSRV legs had hidden that by building on stable.

## Alternatives Considered

- Keep 1.88.0, as the written policy says: rejected by the maintainer in
  favour of one floor across his crates.

## Status

Proposed.
